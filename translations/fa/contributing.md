# مشارکت در کتاب

(contribute-route)=
## انتخاب مسیر

با Markdown و دفترچهٔ ژوپیتر، توضیح اصیل، اصلاح، تحقیق، شکل یا ترجمه ارائه کنید؛ سایت چیدمان را فراهم می‌کند. پیش از کار بزرگ، محدوده را با مدرس هماهنگ کنید تا کار تکراری نشود. مدرس محتوا را علمی بازبینی و درخواست‌های پذیرفته‌شده را ادغام می‌کند.

| مسیر | تحویل |
| --- | --- |
| ویرایشگر مرورگری GitHub | اصلاح کوچک و درخواست ادغام، همراه زبان مقابل |
| فورک و ویرایشگر محلی | شاخهٔ موضوعی با منبع، ترجمه، شواهد عددی و نتیجهٔ ساخت |
| تحویل به مدرس | `.md`/`.ipynb` ویرایش‌پذیر، شکل/داده، منابع، وابستگی‌ها، نام مورد نظر برای اعتبار و فهرست روشن کنترل‌های اجراشده |

اگر ایده ابتدا به فارسی نوشته شده، آن پیش‌نویس را نگه دارید و نسخهٔ انگلیسی را آماده کنید؛ دفترچهٔ انگلیسی منبع عددی مشترک است. در صورت نیاز بازبینی زبانی را در PR درخواست کنید. ترجمهٔ ماشینی بازبینی‌نشده را بررسی‌شدهٔ علمی معرفی نکنید.

(contribute-create)=
## ایجاد محتوا و نسخهٔ زبان مقابل

```sh
git clone https://github.com/YOUR-USERNAME/metasurfaces-book.git
cd metasurfaces-book
git switch -c codex/your-investigation
```

از {download}`templates/chapter-section.md` یا {download}`templates/lab-outline.md` استفاده کنید. متن فصل در `chapters/`، دستور آزمایش در `labs/`، دفترچه در `notebooks/`، کد در `simulations/`، نتیجه در `data/` و شکل در `assets/` قرار می‌گیرد. مسیر متناظر فارسی را زیر `translations/fa/` نگه دارید. [نقشهٔ پیش‌نیاز](learning-path.md) را دنبال کنید و گالری‌های مفهومی سایت همراه را تکرار نکنید.

عنوان، متن، پرسش، زیرنویس، متن جایگزین، فرض و تفسیر را ترجمه کنید. معادله، واحد، علامت، مرجع و شناسهٔ کد را حفظ کنید و [واژه‌نامه](glossary.md) را هماهنگ به‌کار برید. در دفترچه، کدها را دقیقاً یکسان نگه دارید؛ Markdown را ترجمه کنید، خروجی منبع فارسی را خالی و شمارندهٔ اجرا را null بگذارید. ساخت، خروجی عددی انگلیسی را در ویرایش فارسی و بستهٔ اجرایی آن قرار می‌دهد.

(contribute-evidence)=
## اجرا و حفظ شواهد علمی

ابتدا ویرایش را ذخیره کنید؛ هستهٔ دفترچهٔ انگلیسی را از نو آغاز و همهٔ سلول‌ها را به‌ترتیب اجرا کنید. پارامتر، بذر، محیط، صفحهٔ مرجع و علت شکست را ثبت کنید. روشن کنید نتیجه تحلیلی، میدان اسکالر تجویزی، حل تمام‌موج، پیش‌بینی جانشین یا اندازه‌گیری است. حدود تحلیلی، همگرایی کمیت مشاهده‌پذیر و کنترل مستقل مناسب را اضافه کنید. تاریخچهٔ بهینه‌سازی ناموفق را نیز نگه دارید.

از [جدول اجرای همهٔ فصل‌ها، ممیزی و صدور](getting-started.md#setup-run-matrix) استفاده کنید. صدور به مخزن کامل نیاز دارد؛ بستهٔ منبع، کد علمی و ممیزی آن را دارد. با تغییر دادهٔ ورودی، وابسته‌ها را دوباره اجرا کنید: کتابخانهٔ فصل ۳ ← هدایت پرتو فصل ۵ ← مدل‌های جبهه‌موج فصل ۵؛ دادهٔ معیار فصل ۶ را پیش از کنترل دفترچه‌اش بازتولید کنید؛ ms-09/10/11 را پیش از ممیزی/صدور مشترک اجرا کنید.

برای شکل جدید، مولد اصیل یا خروجی برچسب‌خوردهٔ دفترچه را نگه دارید. پس از صدور فصل مرتبط:

```sh
python scripts/export_figure_provenance.py
python scripts/check_notebook_provenance.py --record YOUR-NOTEBOOK-STEM
```

گزینهٔ `--record` تصویری از هویت فایل‌های ذخیره‌شدهٔ بازبینی‌شده می‌گیرد؛ دفترچه را اجرا و علم آن را تأیید نمی‌کند. کد، خروجی، وابستگی/نتیجهٔ ثبت‌شده و رکورد صریح پارامتر را پیوند می‌دهد. دفترچهٔ جدید و وابستگی مستقیم/غیرمستقیم محلی‌اش را در `GROUPS` در `scripts/check_notebook_provenance.py` ثبت کنید. با افزودن شکل، نگاشت مولد منشأ را نیز به‌روز کنید. برای مواد واردشده [راهنمای استفاده و استناد](attribution.md) را ببینید.

## ثبت صفحه در هر دو ویرایش

1. صفحهٔ انگلیسی را در `project.toc` فایل `myst.yml` و متناظر آن را در `translations/fa/myst.yml` اضافه کنید؛ درخت ساخت فارسی همان نام‌های نسبی را دارد.
2. `source`، `translation` و `route` یکتا و پایدار را به `translations/languages.json` اضافه کنید. برای مسیر سفارشی، `slug` صریح MyST را در هر دو صفحه یکسان بنویسید.
3. پیش از عنوان‌های متناظر، برچسب صریح یکسان مانند `(your-investigation-checks)=` بگذارید. این برچسب بخش را هنگام تغییر زبان حفظ می‌کند؛ عنوان ترجمه‌شده به‌تنهایی معمولاً لنگر متفاوت می‌سازد.
4. دو متن را از نظر علمی مقایسه و فقط منابع بازبینی‌شده را ثبت کنید:

```sh
python scripts/update_translation_lock.py chapters/your-section.md
```

قفل منبع، آشکارساز تغییر و ثبت تصمیم بازبینی است؛ کیفیت ترجمه را تشخیص نمی‌دهد. برای خاموش کردن خطا همهٔ هش‌ها را عوض نکنید. وقتی اجرای دوباره خروجی ذخیره‌شده را تغییر می‌دهد، پیش از ثبت قفل جدید دفترچهٔ انگلیسی، برابری کد و نیاز به تغییر تفسیر/زیرنویس را بررسی کنید.

## کنترل نتیجهٔ کامل

محیط علمی را برای آزمون‌های رگرسیون و محیط کتاب را برای ساخت، مطابق [راهنمای نصب](getting-started.md)، به‌کار برید.

```sh
python -m unittest discover -s tests -v
python scripts/check_notebook_provenance.py
python scripts/validate_translations.py
python scripts/export_figure_provenance.py --check
python scripts/build_bilingual.py
```

با سرور ایستای محلی هر دو زبان را ببینید. معادله، شکل، جدول، استناد، پیوند بخش مشترک، نمایش موبایل، کنترل صفحه‌کلید، جست‌وجو و تغییر زبان را بررسی کنید. آزمایشگاه مرورگر در زبانهٔ جدید باز می‌شود و گزینهٔ دانلود ندارد؛ بستهٔ پایتون قابل دریافت است. تغییر تعاملی به کنترل رفتار مرورگر در هر دو زبان نیاز دارد. هندسهٔ تغییرکرده را با مولد SVG اصیل و ابزار محلی‌شده را از قالب/دادهٔ مشترک بسازید.

CI مجموعهٔ محدود تغییر پارامتر، کنترل هویت فایل‌ها و ساخت سخت‌گیرانهٔ دو‌زبانه را اجرا می‌کند. از نتیجهٔ ذخیره‌شده استفاده می‌کند و همهٔ دفترچه‌ها، جاروب‌های پرهزینه یا حل‌گرهای دارای مجوز را دوباره اجرا نمی‌کند. اجرای هستهٔ تازه و بازبینی علمی انسان الزامی جدا هستند. مقایسهٔ بلوک معادلات مرورگر فصل ۲ تضمین همهٔ فیزیک مرورگر یا برابری معنایی کامل فارسی نیست.

## ارائهٔ درخواست ادغام قابل بازبینی

```sh
git add YOUR-CHANGED-FILES
git commit -m "Explain the investigation and its validation"
git push -u origin codex/your-investigation
```

به `metasurface-ir/metasurfaces-book:main` درخواست ادغام بدهید. پرسش آموزشی، مدل/دادهٔ تغییرکرده، پوشش دو زبان، اجرا/کنترل، محدودیت و کمک هوش مصنوعی را توضیح دهید. نام مورد نظر برای اعتبار را ثبت کنید، به منابع اولیه ارجاع دهید و اعلان‌های شخص ثالث را نگه دارید. متن/شکل اصیل کتاب CC BY 4.0 و کد اصیل MIT است؛ فقط محتوایی را ارائه کنید که طبق [سیاست منابع و استفاده](attribution.md) حق انتشارش را دارید.

ارسال تغییر یا موفقیت ساخت PR به معنی انتشار نیست. مدرس کار پذیرفته‌شده را ادغام می‌کند؛ GitHub Pages پس از موفقیت انتشار شاخهٔ اصلی و بررسی مسیرهای عمومی به‌روز می‌شود.
